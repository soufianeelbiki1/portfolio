01 · Flagship

AtlasPay

Payments · Backend · Distributed systems

Problem

Payment systems must remain correct when messages are malformed, responses arrive late, clients retry, and protocols disagree about data representation.

Implemented evidence

  • Strict ISO 8583 MTI and primary/secondary bitmap codec.
  • Fixed, LLVAR, LLLVAR, numeric, text, and binary field validation.
  • Binary DE55 support with malformed-input and property-based round-trip tests.
  • Canonical authorization model separated from the ISO 8583 wire format.
  • Explicit ISO numeric ↔ alpha currency mapping.
  • Response correlation using expected MTI plus STAN and RRN.
  • GitHub Actions quality gate for lint, formatting, compilation, and tests.

Engineering boundary

Network-specific fields are mapped at the adapter boundary so future routing, ledger, risk, events, and ISO 20022 work can operate on a protocol-independent model.

Next vertical slice

Timeout and late-response classification, duplicate windows, reversal linkage, durable idempotency, then ledger/outbox foundations.

Engineering principles

What I optimize for.

Fail closed. Unsupported protocol mappings and malformed inputs should not silently become plausible-looking data.

Test behavior. Edge cases, invariants, property-based tests, and CI matter more than screenshot coverage.

State guarantees precisely. No vague “exactly once” or production-scale claims without evidence.

Add infrastructure for a reason. A modular monolith is preferable to decorative microservices.

Document trade-offs. Architecture should explain why a boundary exists and where it can fail.

Keep the portfolio truthful. Roadmap items are labeled as roadmap items until code and tests exist.
