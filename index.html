01 · Flagship

AtlasPay

Payments · Backend · Distributed systems

Problem

Payment systems must remain correct when clients retry, network messages duplicate or arrive late, external delivery fails, and accounting state must still reconcile.

Implemented evidence

  • Strict ISO 8583 codec plus canonical authorization mapping and STAN/RRN correlation.
  • Durable PostgreSQL request and operation idempotency with explicit conflict detection.
  • Append-only, balanced double-entry ledger integrated atomically with capture/refund/reversal state.
  • Transactional outbox with explicit at-least-once delivery, consumer deduplication, retries, and poison-message retention.
  • Deterministic reconciliation reports and bounded replay controls that never silently rewrite accounting history.
  • Transport-independent network coordination for accepted, timeout, late-response, duplicate, and mismatch outcomes.
  • Issuer/acquirer routing with deterministic longest-prefix selection plus one-to-one reversal correlation.
  • Strict DE55 BER-TLV parsing with constructed templates, EMV tag metadata, and five-byte TVR decoding.
  • Byte-oriented transport adapter plus timeout→reversal lifecycle with explicit delivery ambiguity and late-response classification.
  • GitHub Actions gates for lint, formatting, migrations, compilation, and integration tests.

Engineering boundary

Database atomicity is stated precisely; external broker/network delivery is not mislabeled as exactly-once. Protocol, ledger, outbox, reconciliation, and network coordination remain separate modules.

Next vertical slice

Scoped ISO 20022 interoperability is under review; observability and fault-injection around the network lifecycle follow.

02 · AI system

AtlasRAG

Retrieval · Evaluation · LLM engineering

A deterministic retrieval baseline now feeds a citation-first query service with explicit abstention when evidence is absent or too weak.

  • Typed query, evidence, citation, and response contracts.
  • Deterministic lexical retrieval with precision/recall@k and MRR evaluation primitives.
  • Generator/provider boundary with a credential-free extractive reference implementation.
  • FastAPI query endpoint that returns cited evidence or abstains instead of inventing support.
  • Deterministic ingestion identity with normalized fingerprints, stable chunk IDs, replay semantics, and explicit document-ID conflicts.
  • Durable PostgreSQL document/chunk persistence with unique constraints, advisory-lock retry serialization, and concurrent replay tests.
  • Reciprocal-rank fusion across retriever ports plus a separate reranking contract, without pretending backend raw scores are calibrated.

Status: query/evaluation, durable ingestion, hybrid rank fusion, and reranking contracts implemented; a measured semantic/vector adapter is next.

03 · Platform surface

Nexus

Platform · Operations · Control plane

Nexus is now a typed AtlasPay operator surface with provenance-aware snapshot loading, explicit stale/partial/unavailable states, issuer health, incidents, and network transaction drill-down.

  • Snapshot source boundary with runtime validation that refuses to render malformed or unavailable telemetry.
  • STAN/RRN transaction outcomes with latency availability and reversal correlation/reason.

04 · Applied ML

ForecastLab

Computer vision policy · Evaluation · Explainability

ForecastLab now has an explainable passport-photo compliance policy boundary over measured observations, with deterministic per-rule evidence and synthetic regression tests before heavyweight CV models are introduced.

  • Rule evaluation for dimensions, face count, pose, background uniformity, and occlusion.
  • Versionable thresholds with explicit input validation and measured evidence strings.
  • Estimator interfaces for pose/background/occlusion/quality signals with deterministic doubles in CI.
  • Versioned quality policy for blur, compression, illumination, and shadow with synthetic rule-level regression metrics.
  • FastAPI precomputed-signal evaluation returning policy/estimator versions and per-rule evidence; raw-photo inference is not claimed.
  • Synthetic-only CI fixtures; no raw passport or identity photos are stored.

Status: evaluator and quality-policy foundations implemented; no real-world accuracy or certification claim.

Engineering principles

What I optimize for.

Fail closed. Unsupported protocol mappings and malformed inputs should not silently become plausible-looking data.

Test behavior. Edge cases, invariants, property-based tests, integration tests, and CI matter more than screenshot coverage.

State guarantees precisely. No vague “exactly once,” live-telemetry, production-scale, or model-accuracy claims without evidence.

Add infrastructure for a reason. A modular monolith is preferable to decorative microservices.

Document trade-offs. Architecture should explain why a boundary exists and where it can fail.

Keep the portfolio truthful. Roadmap items are labeled as roadmap items until code and tests exist.
